Brain-Score · Unified Model Interface

What actually changes — and what doesn’t

The Unified Model Interface (UMI) changes how a benchmark talks to a model. It does not change the models, the data, the metrics, or the scores. Here is the difference, without the vocabulary.

How a benchmark evaluates a model

Today · brainscore-vision + brainscore-language
Two interfaces, one per domain
Input · one batch
A StimulusSet — every image handed over at once. A language benchmark hands over text instead.
▾
look_at(images) start_recording('IT') start_task(…) digest_text(text)
reached through several domain-specific methods
The model a BrainModel (vision) or ArtificialSubject (language)
▾
Output · one batch
A NeuroidAssembly / BehavioralAssembly — returned all at once.

Batch in, batch out. Vision and language use different methods and different model types — a model is registered once per domain, and a new kind of experiment has no method at all.

With UMI
One interface, every experiment
Input · a stream
Input events, arriving over time — vision · text · audio · lesion:… each stamped with a time, t_ms
▾
subject.interact(session)
one method, whatever the experiment
The subject a model — or, in principle, a human
▾
Output · a stream
Output events, emitted over time — neural:IT · behavior · motor each stamped with a time, t_ms

One method, a two-way stream. A new kind of experiment is a new channel, not a new method — and the same contract a human could satisfy.

What “streaming” means

Those input and output boxes are not batches — they are streams. A benchmark opens a session and events flow both ways over time, each stamped with when it happened (t_ms). The subject pulls the next input and emits its responses on its own clock. A timeless model just answers each input as it arrives; a model with internal dynamics can also act between them. Each mark is a StreamEvent — a channel, a payload, and a t_ms. Inputs stream in (scrolling left); the subject’s responses stream out (scrolling right).

Same data, delivered as one block in and one block out. The pieces are all there, but when each one happened is not — there is no time axis to place them on. UMI keeps that timing, so a model with its own dynamics can act between inputs, and a continuous movie or a closed loop fits the same contract.

What stays identical underneath

Same
science

Same weights, same preprocessing, same layer extraction, same caching, same metrics — so a benchmark returns the same score, bit-for-bit. Existing models and benchmarks are never removed: a legacy model runs through an adapter that turns interact() back into look_at() / digest_text(). UMI changes the doorway, not the room.

Concretely: CLIP, registered once as a subject, is scored by a vision benchmark (it emits on neural:IT), a language benchmark (neural:language_network), and a reading-behavior benchmark (behavior) — with no re-registration.

Today, that is three separate model submissions across two repositories.

The vocabulary, decoded

UMI termIn plain EnglishWhat it replaces today
Subject The thing being tested — a model, or in principle a human. BrainModel (vision) and ArtificialSubject (language) — two separate types.
interact(session) The single call a benchmark makes to run the model. look_at + start_recording + start_task + digest_text — several different calls.
StreamEvent One timestamped piece of data on a channel — an image, a sentence, a spike. A StimulusSet row going in, or an assembly coming out.
channel The labeled wire a piece of data travels on. Implied by which method you happened to call.
Session The two-way stream between benchmark and model, over time. The benchmark’s own loop of method calls.
neural:IT An output channel meaning “record from region IT.” start_recording('IT').
behavior An output channel carrying a choice or an answer. The readout set up by start_task.
lesion:… An input channel meaning “switch off these units.” No equivalent — would need a new method.
motor An output channel carrying an action in a world. No equivalent — would need a new method.

Why bother — three things it unlocks

one model → every domain

No more per-domain silos

A single registration is scored on vision, language, and behavior benchmarks alike, instead of one submission per domain across two codebases.

new experiment = new channel

Extend without touching the interface

Lesioning, stimulation, and embodied action are added as channels in a registry — not as new methods threaded through every benchmark.

model ≡ human

The same test on a person

Because the contract never assumes the subject is a model, the identical benchmark can, in principle, be run on a human — the strongest check of “brain-like.”
