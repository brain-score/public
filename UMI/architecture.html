The architecture, end to end.

Every subject registers once and is evaluated through a single method — interact(session). A subject exchanges timestamped events over named channels, and a channel registry documents every allowable input and output. This page draws out the full contract and the exact routing. A single-tower subject on a movie is ◐ partial — it reads only its one channel. An output-only / black-box subject (a closed API, an embodied policy) is a genuine limit for neural encoding and lesioning: no internal activations.

The contracts

The full surface. These are the only things a model author touches; everything else (dispatch, caching, compatibility, memory) is handled by the framework.

1 · The core artifacts

A subject exchanges timestamped events over named channels through one method. Direction is set by who produces the event — the world produces inputs, the subject produces outputs.

@dataclass
class StreamEvent:                # the carrier for BOTH inputs and outputs
    channel: str                  # 'vision' · 'neural:IT' · 'motor' · 'lesion:V4'
    payload: Any                  # shape/dtype defined by the channel registry
    t_ms: float                   # time on the session clock
    meta: dict

class Session(ABC):               # the duplex; open- vs closed-loop differ only here
    def next_input(self) -> StreamEvent | None: ...   # None ends the stream
    def emit(self, event: StreamEvent) -> None: ...    # receive a subject's output

class Subject(ABC):               # the minimal interface every subject satisfies
    in_channels:  set[str]        # channels it can consume
    out_channels: set[str]        # channels it can emit
    def interact(self, session: Session) -> None: ...  # the ONE evaluation method
    def reset(self) -> None: ...                        # clear state / active perturbations

interact pulls input events and emits output events over the subject's own time. Open- and closed-loop are indistinguishable from inside it — the session owns that distinction. A model implements it directly; a human harness implements it by mediating a biological subject.

2 · Channels — the grammar

A channel name is family or family:address. Channels are the only extension point: a new modality, readout, device, or perturbation is a new registry entry, never a new method or event type.

DirectionFamilies
Inputvision · text · audio · video · instruction · proprioception · lesion:<addr> · stimulation:<addr> · pharmacological:<agent>
Outputneural:<region> · behavior · motor · pupil · skin_conductance

For neural:<region> the address is a recordable region; for lesion: / stimulation: it is a unit selector (a layer path, optional indices) interpreted by the harness. Recording and perturbation share one address grammar.

3 · The channel registry — where payload shapes are pinned down

Because a payload is opaque at the Python type level, the registry is what keeps the substrate disciplined. It is a documented, runtime-queryable table; each entry defines a channel's direction, payload contract (dtype / shape / units), recognized meta keys, address grammar, and owner. A new sense, device, or readout is a registry row; nothing in the Subject contract changes.

4 · The typed helpers — the everyday surface

The substrate is general; the everyday surface is typed and ergonomic. Each helper builds a session, calls interact, and collects the output into the assembly the metrics already consume. Benchmark authors almost never touch a raw StreamEvent.

neural_response(subject, stimulus_set, record='IT')  -> NeuroidAssembly
behavioral_response(subject, task_context)              -> BehavioralAssembly
apply_state_change(subject, state_change)          -> handle          # lesion / stimulation
run_environment(subject, environment)              -> trajectory       # closed-loop motor

6b · Time — the time_bin axis + the temporal kit

Naturalistic benchmarks need when, not just what. The rule is one line: the model always emits time-resolved features at its own native rate, and the benchmark owns the model→brain time alignment. A benchmark with no native time is just the N=1 case of the same machinery — one bin. Every output carries the canonical coords time_bin_start_ms / time_bin_end_ms, so a benchmark aligns any wrapper uniformly. Here is what that looks like in both cases.

Case A — a benchmark with no native timebins (static images, e.g. MajajHong IT). The still-image wrapper has no time axis; add_time_bin_axis stamps one bin = the neural recording window:

still-image wrapper   ->  (2560 images, 168 neuroids)              # 2-D, no time axis
add_time_bin_axis(a, time_bin_start_ms=70, time_bin_end_ms=170)
                      ->  (2560 images, time_bin=1, 168 neuroids)
                          time_bin_start_ms = [70]   time_bin_end_ms = [170]   # the (70,170) ms
                                                                               # V1-IT response window
# One bin, stamped with the recording window. The metric runs on it exactly as
# the old 2-D shape -> static scores are unchanged bit-for-bit.

Case B — a benchmark with native timebins (movie → fMRI, e.g. Lahner / Algonauts). The stimulus is one clip; the model runs at its native frame rate, then temporal_bin pools those frames onto the brain's TR grid:

1. preprocessor  expand_clip_to_frames  ->  each frame carries frame_time_ms + clip_id
2. time-aware wrapper (native rate)     ->  (SUM frames over clips, neuroids)  [frame_time_ms, clip_id]
3. temporal_bin(a, [(0,1750),(1750,3500),(3500,5250)])          # TR = 1750 ms, bins half-open [start,end)
                      ->  (n_clips, n_TRs, neuroids)             # frames in a bin are mean-pooled; empty -> NaN
                          time_bin_start_ms = [0, 1750, 3500]   time_bin_end_ms = [1750, 3500, 5250]
4. hrf_convolve(a, ...)  ->  warp model-time into BOLD-time (double-gamma, ~5 s peak) before the ridge fit
# The clip's onset in the run (events sidecar) puts frame_time_ms on the brain's
# absolute clock; contiguous_block_cv splits it (BOLD is autocorrelated, not i.i.d.).

Same operation both times. temporal_bin down-samples the model's native rate onto the brain's grid; add_time_bin_axis is that operation with a single bin = the recording window. The shared kit in core/brainscore_core/temporal.py:

HelperDoes
add_time_bin_axisCase A: promote a still-image wrapper's 2-D output to a single time_bin, stamped with the recording window
temporal_binCase B: pool per-frame/token features into requested TR windows (half-open, mean/first, empty→NaN)
hrf_convolveBOLD-aware: convolve model features with the hemodynamic response before fitting fMRI
contiguous_block_cvblock cross-validation for autocorrelated time series
window_plantile a clip longer than a model's native window into block/causal windows

A clip longer than a video model's native temporal window does not silently downsample: VideoWrapper(context_window_ms=…) uses window_plan to chunk it, forwards each window, and stitches the per-window time-resolved features into one clip-time sequence with absolute timestamps (max_clip_ms gives a fail-fast). Model→brain time alignment lives in the benchmark (temporal_bin + hrf_convolve), not a commitment layer — the same reason regions map to layers freely rather than through a fixed hierarchy.

7 · Inside interact — dispatch by channel

def interact(self, session):
    # Drain the session's input events, read which channels it wants back,
    # run the extraction, and emit output events. A subject dispatches on the
    # requested OUTPUT channel — never on a hardcoded event-type ladder.
    for channel in session.requested_output_channels:
        if   channel.startswith('neural:'): emit_neural(session, region_of(channel))
        elif channel == 'behavior':         emit_behavior(session)     # readout or generation
        elif channel == 'motor':            drive_closed_loop(session) # live: act, observe, repeat
        elif channel == 'perturbation':     apply_and_ack(session)     # lesion / stimulation
    # A new output family is a new registry channel + one emit-branch;
    # the substrate and every existing benchmark are untouched.

The perceptual path is the 99% case: input events on vision / text / audio / video flow through the matching preprocessor and the shared activations model, extracting every recorded region's layer in one forward pass. A multimodal input fans out to every tower and concatenates along the neuroid axis with a per-neuroid modality coord.

8 · Compatibility — checked before compute

Run as a pre-flight check (then a memory probe) before any benchmark, so mismatches fail in milliseconds instead of mid-extraction. A benchmark declares its required input and requested output channels; a subject declares what it can consume and emit:

benchmark.required_input_channels   ⊆ subject.in_channels
benchmark.requested_output_channels ⊆ subject.out_channels
subject.required_channels           ⊆ benchmark.required_input_channels

An incompatible pair displays as N/A, never a misleading zero. A benchmark declares exactly one input format; multiple valid formats are separate benchmark variants. A text-only subject's required={text} is what makes it fail fast on a V4 image benchmark. check_memory() then runs the stimulus set through the subject as an extraction probe, measures peak memory (CUDA / MPS / CPU), and estimates metric + ceiling memory.

Extending it — five inherited seams + the channel seam

The interface is a backbone: a small, stable core you extend along well-defined seams. Model / Benchmark / Metric / Data / Stimulus-set are Brain-Score's existing plugin registries, reused unchanged; the channel registry and its harnesses are the seam the unified interface adds. We ship the seams + a few reference integrations; you bring the breadth. Extending happens by registration, not by editing the core.

One mechanism: registries

Everything is a factory registered under a string identifier. A plugin is a subpackage whose __init__.py adds a factory to the matching registry; you then load by id.

import brainscore
data      = brainscore.load_dataset('your-data')          # vision/language registry
stimuli   = brainscore.load_stimulus_set('your-stimuli')  # reused across benchmarks
metric    = brainscore.load_metric('your-metric')         # the metric seam, now first-class
benchmark = brainscore.load_benchmark('your-benchmark')
score     = brainscore.score('your-model', 'your-benchmark')

load_* checks the unified registry first, then falls back to the vision / language registries, so every registered model and benchmark keeps working. Five registries — data, stimulus_set, metric, benchmark, model — sit alongside the channel registry, which documents every allowable input and output. A new channel is a self-registering entry, not a hard-coded branch.

The Metric seam is where the field is moving — beyond linear predictivity toward representational, topographic, behavioral, and causal alignment. Each distinct axis is a distinct metric (e.g. load_metric('topographic-alignment') scores a model's spatial unit layout against cortical topography, which predictivity is blind to — it is permutation-invariant over units). On the input/output side, a new modality, readout, device, or perturbation is a new channel: a registry entry plus a harness that reads or emits it, with zero edits to BrainScoreModel or the Subject ABC — Open/Closed. The channels the interface ships with — sensory input, neural, behavior, motor, perturbation, and reserved physiological readouts — are all registry entries; a new one is a new entry, not a new method, and a drift guard pins the registry so the contract and the docs cannot silently diverge.

The topographic axis, on real fMRI (a first n=2 sign-check). Scored on an NSD fsaverage-surface target through this exact seam:

modeltopographic alignment (signal vs. shuffle null)
CLIP ViT-B/32 (non-topographic)−0.155 — sits below the null (correct negative control)
TDANN (topographic ResNet-18)+0.838 — its unit layout matches the cortical sheet

Predictivity cannot tell these apart; the topographic metric + a position-shuffle null can. There are two topographic axes: this one (units correlated across stimuli, which TDANN is organized on) and a selectivity axis (units sharing category preference, which a model like Topo-Omni is organized on) — distinct metrics, because the metric must match the axis the model was smoothed on.

What the backbone deliberately leaves to you: discovery / analysis pipelines (they consume the collected assemblies — ship them as scripts, not core primitives), model-internal descriptors that don't compare to the brain, model training, and catalog breadth.
